# SQL Database & Analytics Engineering Interview Preparation

This revision guide prepares you for technical interviews spanning **Relational SQL Databases**, **Analytics Engineering**, **Power Query / Data Modeling**, and **Portfolio Project Defense**.

---

## 1. Conceptual & Database Architecture

### Q1: What is the core difference between OLTP and OLAP systems?
> **Answer**: OLTP (Online Transaction Processing) systems are designed for high-concurrency, fast, row-level write and update operations (3NF normalized to prevent anomalies), powering daily operational apps. OLAP (Online Analytical Processing) systems are optimized for read-heavy, multi-dimensional analytical queries across historical data, typically organized as denormalized star schemas with columnar storage.

### Q2: Why are surrogate keys preferred over natural keys in data warehouses?
> **Answer**: Natural keys are subject to operational changes, format migrations, and reuse. Surrogate keys are immutable, integer-based identifiers generated by the data warehouse pipeline. They optimize join performance (smaller integer footprint compared to string keys), decouple analytical models from source system churn, and enable tracking history via Slowly Changing Dimensions (SCD Type 2).

### Q3: What is "Database Grain" and why does it matter?
> **Answer**: Grain represents the exact level of detail represented by a single row in a table (e.g., one line item vs one invoice header). Establishing grain is essential to prevent joining tables at mismatched grains, which leads to Cartesian fan-out and duplicated financial measures.

## 2. Advanced SQL Technical Questions

### Q4: Explain the difference between `WHERE` and `HAVING`.
> **Answer**: `WHERE` filters individual rows *before* any grouping or aggregation takes place. `HAVING` filters group-level summaries *after* the `GROUP BY` clause evaluates aggregations.

### Q5: What is the difference between `RANK()`, `DENSE_RANK()`, and `ROW_NUMBER()`?
> **Answer**: 
> - `ROW_NUMBER()` generates unique sequential numbers (1, 2, 3, 4).
> - `RANK()` assigns identical rank to tied values, skipping subsequent ranks (1, 2, 2, 4).
> - `DENSE_RANK()` assigns identical rank to tied values without skipping numbers (1, 2, 2, 3).

### Q6: How does a Common Table Expression (CTE) differ from a temporary table or subquery?
> **Answer**: A CTE is a named temporary result set defined in memory for the duration of a single statement. It significantly improves readability over deeply nested subqueries and supports recursion. Unlike physical `#TempTables`, CTEs do not persist in `tempdb` and cannot be indexed independently.

## 3. Analytics Engineering & Ingestion

### Q7: What is Power Query "Query Folding" and why is it important?
> **Answer**: Query folding is the translation of Power Query M transformations into native SQL queries pushed directly to the source database engine. It ensures high performance by filtering and aggregating data on the SQL Server before network transmission, avoiding pulling millions of raw rows into Excel memory.

### Q8: How do you decide whether a transformation belongs in SQL, Power Query, or DAX?
> **Answer**: 
> - **SQL**: Upstream relational joins, row filtering, column pruning, and enterprise semantic views.
> - **Power Query**: Workbook-level parameterization, unpivoting, local file merges, and data type alignment.
> - **DAX**: Dynamic aggregations, ratio metrics (`Margin %`), and filter-context sensitive calculations responsive to dashboard slicers.

## 4. Portfolio Project Defense Questions

### Q9: In the `pubs` project, how did you handle the Many-to-Many relationship between authors and titles?
> **Answer**: *"Titles and authors have an M:N relationship resolved by the `titleauthor` bridge table. A naive join between titles, titleauthor, and sales duplicates sales revenue for co-authored books. To solve this, I authored a CTE in SQL that weighted sales revenue by each author's explicit royalty share (`ta.royaltyper / 100.0`) before aggregating. I validated that the total allocated royalties matched the underlying raw sales amount of $42,891.00."*

### Q10: Why did you create a SQL View rather than connecting Excel directly to the tables in AdventureWorks?
> **Answer**: *"Direct table connections tightly couple Excel workbooks to operational database schemas. By creating `dbo.vw_ExecutiveSalesPipeline`, I established an abstraction layer. The view handles schema navigation across Sales, Production, and Person schemas, projects only relevant columns, and ensures that Power Query preserves query folding. Furthermore, if the underlying operational tables undergo maintenance or migration, the Excel workbook remains stable as long as the view contract is preserved."*

### Q11: How did you validate that your Excel dashboard reconciles with the database?
> **Answer**: *"I implemented a 4-Tier Reconciliation Audit:
> 1. **Tier 1 (Row Count)**: Verified that the 121,253 rows in the SQL view matched the imported Power Query row count exactly.
> 2. **Tier 2 (Key Completeness)**: Audited distinct order and customer keys to confirm no inner join dropped valid records.
> 3. **Tier 3 (Financial Reconciliation)**: Reconciled total gross revenue ($109,809,274.20) and gross profit ($12,551,366.25) between raw SQL queries and DAX measures.
> 4. **Tier 4 (Channel Segmentation)**: Verified that Internet sales ($29.36M) and Reseller sales ($80.45M) balanced across every dimension."*
